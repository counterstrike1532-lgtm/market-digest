# CLAUDE.md

Контекст проекта. Читай целиком перед любой задачей. Состояние на 03.08.2026, всё работает.

## Что это

Утренний дайджест в Telegram: отобранные сюжеты (Польша, США, рынки, ИИ) + свежие цифры
из первоисточников + черновики постов для LinkedIn на английском.

Владелец: студент 2 курса Finance & Accounting, Kozminski University, Варшава.
Цель — investment banking / asset management. Общается по-русски, код и посты на английском.

**Приоритет ценности:** первая задача дайджеста — держать владельца в курсе рынков для
собеседований (в IB это спрашивают напрямую). Черновики постов — побочный продукт.
Не оптимизируй под виральность, оптимизируй под содержательность и проверяемость.

## Стек

- Python 3.14 на машине владельца (Windows 11, PowerShell 5.1); в проде (GitHub Actions) - 3.12
- Зависимости (`requirements.txt`): `requests`, `feedparser`, `PyYAML`, `matplotlib` (графики),
  `yfinance` (рынки). Новые — только с явного разрешения владельца
- LLM: Gemini free tier. Модели по умолчанию: `gemini-3.5-flash,gemini-3.6-flash,gemini-3.1-flash-lite`
- Прод — GitHub Actions (`.github/workflows/digest.yml`, cron будни 07:17 по Варшаве), репо
  **публичный** (приватная квота минут занята другим ботом владельца). `.\run.ps1` — для
  разработки и ручной проверки, не для регулярной отправки
- Всё на бесплатных лимитах. Это жёсткое требование, платные API не предлагать

## Архитектура

```

src/enrich.py         догрузка текста статей для отобранных сюжетов

                       и single A/B/C; digest-short убран в T11e)

                       -Markets, не в ежедневной отправке (T11e)
src/chartstyle.py     общий вид графиков (цвета/шрифты, light/dark)
src/metrics.py        тихое накопление state/metrics.json на будущее (T9d), в Телеграм не идёт
src/deliver.py        Telegram, нарезка по 3900 символов
src/main.py           оркестрация, --dry для прогона без отправки
src/verify_feeds.py   проверка живости фидов

src/score_draft.py    локальный скорер готового черновика (--deep зовёт Gemini)
```

Поток: собрать → дедупнуть → цифры → отбор Gemini → догрузить статьи → черновики →
верификация чисел → Telegram. Отказ Gemini на любой из трёх LLM-стадий (отбор/черновики/
верификация) не роняет прогон и не даёт пустого сообщения — цифры и эвристический отбор
уходят всегда (T13a).

# ГРАБЛИ, НА КОТОРЫЕ УЖЕ НАСТУПИЛИ

Всё ниже было отлажено ценой целого дня. **Не откатывай это, даже если выглядит избыточным.**

1. **`.ps1` файлы — ТОЛЬКО ASCII.** PowerShell 5.1 читает их как Windows-1251, если нет BOM.
   Любая кириллица в `setup.ps1` или `run.ps1` ломает парсер намертво. Сообщения по-английски.

2. **Каждое чтение файла — с `encoding="utf-8"`.** `Path.read_text()` без аргумента берёт
   системную кодировку (cp1251) и падает на кириллице в конфиге. Проверяй все новые
   `read_text` / `write_text` / `open`.

3. **Не отправляй `thinkingConfig.thinkingBudget: 0` моделям `gemini-3*`.** Они отвечают 400.
   В `_call` есть проверка `not model.startswith("gemini-3")` — она нужна.

4. **JSON от Gemini обрывается**, если поля длинные: токены размышлений тратятся из
   `maxOutputTokens`. Поэтому в `RANK_PROMPT` жёстко ограничена длина `angle` (20 слов) и
   `why_nonobvious` (15 слов), а `_parse_json` умеет спасать частично обрезанный массив.
   Не убирай ни то, ни другое.

5. **400 от Gemini детерминирована.** Не ретраить одним и тем же телом. `_call` снимает
   необязательные параметры по одному и логирует тело ответа — так и оставь.

6. **Free tier ловит 429.** Батч отбора 25, пауза между батчами 7 секунд. Не уменьшай паузу.

7. **Reddit отдаёт 403** почти всегда, даже с браузерным UA. Это норма, не «баг для починки».
   RSS даёт ~280 записей, Reddit не нужен.

8. **NBP не имеет новостного RSS вообще.** Не ищи его. Курсы берутся через api.nbp.pl
   в `numbers.py`, новости про RPP — через Google News запрос в конфиге.

9. **Google News RSS** — обычный RSS с параметром `q=`. Так закрыты источники без своих
   фидов. Меняешь `q=` в конфиге, код не трогаешь. Текст статей по этим ссылкам
   не догружается (редирект-обёртка), `enrich.py` их сознательно пропускает.

## Правила, которые нельзя нарушать

1. **Каждый внешний вызов в try/except.** Упавший источник логирует warning и не ломает прогон.
2. **Никаких новых зависимостей** без явного разрешения владельца.
3. **`RANK_PROMPT` — сердце качества.** Список критериев отбраковки намеренно жёсткий,
   не размягчай. Требование разброса оценок обязательно: без него всё сваливается в 8/10.
4. **Цифры только проверяемые.** Модель отбора видит лишь заголовок и обрывок описания,
   поэтому в `DRAFT_PROMPT` запрещено использовать числа, которых нет в догруженном тексте
   статьи или в блоке `FRESH DATA`. Выдуманная цифра в посте под настоящим именем — худший
   возможный исход. Это правило приоритетнее красоты текста.
5. **Позиция объясняющая, не вопросительная.** Не «что я упускаю?», а «вот почему механизм
   работает так». Фразы `I might be wrong`, `What am I missing` — в чёрном списке промпта,
   владелец возражал против них прямо. Не возвращай.
6. **Антишлак-правила в `DRAFT_PROMPT`** (запреты на leverage/synergy/emoji/engagement-bait,
   требование разных структур A/B/C) не удалять: LinkedIn душит охват такому контенту,
   а целевая аудитория — аналитики — видят LLM-ритм насквозь.
7. **Секреты только через env.** Никогда не хардкодь и не логируй ключи. `secrets.ps1`
   в `.gitignore`, репо публичный.

## Как тестировать

```powershell
.\run.ps1 test      # pytest, только моки, живая сеть/Gemini не нужны
.\run.ps1 verify    # живость фидов, ключи не нужны
.\run.ps1 models    # доступные модели Gemini
.\run.ps1 dry       # полный прогон без отправки, живая сеть и ключи нужны
.\run.ps1 send      # с отправкой в Telegram
.\run.ps1 score draft.txt [-Deep]   # локальный скорер готового черновика
```

Юнит-тестов на моках много (`tests/`, ~190+, растёт с каждым ТЗ) — они покрывают парсинг,
верификацию чисел, рендер сообщений и т.д. без единого живого вызова Gemini или сети.
Финальную приёмку фичи всё равно делает владелец глазами по выводу `--dry` — тесты ловят
регрессии, не заменяют живой прогон.
