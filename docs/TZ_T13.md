## T13a — деградированный режим

Проблема: неизвестно, что приходит в Телеграм, если Gemini недоступен —
исчерпана квота на всех трёх моделях, таймаут, 5xx, невалидный JSON после
сальважа. Цифры NBP/рынков/HICP и эвристический предфильтр не требуют модели и
должны уходить всегда. Дайджест без черновиков ценнее пустого утра.

### Шаг 0 — отчёт до кода

Трассировкой по коду, без запусков, описать в чат текущее поведение для каждой
строки матрицы ниже: что происходит с процессом и что реально уходит в Телеграм.
Где поведение уже правильное — не трогать и так и написать.

### Матрица отказов

Три стадии независимы: отбор (rank), черновики (draft), верификация (verify).

| Падает | Требуемое поведение |
|---|---|
| rank | Эвристический top-N вместо ранжирования модели, в сводке строка, что отбор шёл без модели. Черновиков нет. |
| draft | Сводка уходит полностью. Одна строка: черновиков сегодня нет, с причиной (квота / ошибка модели). |
| verify | Черновики уходят. Картинки нет (нет чисел со статусом FOUND). Одна строка на сообщение: числа не верифицированы. **Не** проставлять ⚠️ на каждое число — это alarm fatigue. |
| всё | Блок цифр (NBP, рынки, HICP — они без LLM) + эвристический top-N + строка про отсутствие черновиков. |

### Инварианты

- Ни один отказ Gemini не приводит к пустому сообщению и не роняет процесс:
  дайджест доставлен → exit 0 + WARNING в лог. Только недоставка — ненулевой код.
- `_day_exhausted` уважается: никаких ретраев исчерпанной модели в том же прогоне.
  Общее число попыток вызова за прогон не растёт по сравнению с текущим.
- Ошибки сети и Telegram API — вне области задачи.
- Формулировки строк-пометок — обычным текстом сводки, без новых эмодзи-маркеров.

### Тесты — `tests/test_degraded.py`

- По одному тесту на строку матрицы: `brain._call` мокается так, чтобы бросать
  на нужной стадии.
- Проверять состав итогового сообщения: присутствует блок цифр, присутствует
  N сюжетов, присутствует ожидаемая строка-пометка, отсутствуют черновики там,
  где их не должно быть.
- Отправка в Telegram мокается; тест не шлёт ничего наружу.
- Явный ассерт: реальных вызовов Gemini ноль, число попыток соответствует
  ожидаемому (нет скрытых ретраев).
- T11a (`NEWSBOT_ALLOW_LIVE`) остаётся второй линией защиты, но тест не должен
  на неё опираться как на основную — мок ставится явно.

## T13c — локальный `send` не трогает `state/`

Проблема (грабля 6): локальный `send` записал и закоммитил состояние, вечерние
сюжеты стали виденными для утреннего прогона, откатывалось руками.

Правило: **состояние публикует только Actions.**

- Локальный запуск не изменяет файлы в `state/` и ничего не коммитит.
- Гейт по переменной окружения, по аналогии с `NEWSBOT_ALLOW_LIVE`; ставит её
  только шаг в `digest.yml`.
- Флаг `run.ps1 send -PersistState` — явное локальное сохранение, если владелец
  осознанно этого хочет.
- `run.ps1` остаётся ASCII-only; файловый ввод-вывод в Python — с явным
  `encoding="utf-8"`.

Тесты: без переменной запись состояния не происходит; с переменной происходит.
Путь к `state/` в тестах подменяется на временный каталог.
