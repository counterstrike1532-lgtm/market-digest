## T8a — модуль графиков

### Зачем

Картинки к сводке и к постам. Ноль запросов Gemini: все данные уже в пайплайне.

### Новая зависимость

`matplotlib` — добавить в requirements.txt. Это единственная новая зависимость,
владелец разрешил. Ничего больше (никаких seaborn/plotly/pillow).

### Стиль (главное требование владельца)

Не «как в Excel». Современная карточка: тёмный фон, крупная типографика, один акцентный
цвет, минимум чарт-джанка. Реализовать как словарь rcParams в src/chartstyle.py:

- две темы: dark (фон #16161a, текст #f5f5f5) и light (фон #fafafa, текст #1a1a1a);
  выбор параметром theme="dark"|"light"
- акцентный цвет один: #A9082C (бургунди), второй ряд — нейтральный серый #8a8a8a
- НЕТ: рамок осей сверху/справа, сетки по X, легенд в рамке, 3D, теней
- ЕСТЬ: тонкая горизонтальная сетка (alpha 0.15), подписи значений прямо у концов линий
  вместо легенды, заголовок крупно слева, источник и дата мелко внизу
  ("Data: NBP, stooq | 30.07.2026")
- шрифт DejaVu Sans (есть везде, включая ubuntu-раннер), заголовок ~20pt bold
- размер 1200x675 px (16:9, нормально смотрится и в ТГ, и в LinkedIn), dpi=150, PNG

Темы должны давать читаемый контраст: проверить, что подписи значений видны на обеих.

### src/charts.py — две функции

1. market_overview(numbers, theme) -> path | None
   Стандартный график к каждой сводке: WIG20 и S&P 500 за ~45 дней, нормированные к 100
   на первую дату, две линии. Подпись последнего значения у конца каждой линии
   (например "WIG20 +4.1%"). Данные: расширить numbers.py, чтобы stooq_series
   возвращал не только последние значения, но и весь ряд (даты + close) — он и так
   скачивается целиком, сейчас просто выбрасывается. НЕ ломать существующий формат
   вывода gather(): добавить ряды отдельным ключом.

2. figures_chart(figures, title, theme) -> path | None
   График из цифр черновика. На вход — распарсенный список пар (значение, подпись)
   из блока FIGURES лучшего черновика. Логика выбора типа:
   - 2-5 именованных значений -> горизонтальные бары
   - пары "было/стало" или проценты роста -> два бара рядом
   - если структура не распознана -> вернуть None и НЕ рисовать
   Правило без исключений: рисуем ТОЛЬКО числа из FIGURES, у которых указан источник.
   Никогда не досочинять ряды. График с выдуманной цифрой хуже текста с выдуманной
   цифрой — картинка разлетается без контекста.

### Отправка

deliver.py: функция send_photo(path, caption) через sendPhoto (multipart/form-data).
Caption до 1024 символов, HTML-режим как в send().

### Интеграция в main.py

- после сбора цифр: market_overview(theme="dark") -> отправить фото ПЕРЕД текстовой
  сводкой с коротким caption ("Рынки за месяц")
- после черновиков: если у лучшего черновика распарсился FIGURES -> figures_chart
  (theme="light", т.к. это заготовка для LinkedIn) -> отправить после черновиков
  с caption "График к черновику 1 — можно приложить к посту"
- флаг --no-charts для отключения
- ошибка в графиках НЕ валит прогон: try/except, warning, сводка уходит текстом

### Actions

Ничего не менять: matplotlib поставится через requirements.txt, Agg-бэкенд работает
без дисплея (задать matplotlib.use("Agg") до pyplot).

## T8b — черновики как дайджест-посты, два варианта

### Зачем (стратегия владельца)

Владелец определил роль постов: не «аналитик», а «начитанный активный студент».
Формат — недельный/регулярный дайджест: 2-3 вещи, которые показались важными, и почему.
Скромная рамка, без претензии на экспертизу. Это снижает риск репутации и проще пишется.

### Правки DRAFT_PROMPT

1. Сменить формат выхода. Вместо трёх постов по разным сюжетам:
   - DRAFT 1 (digest): пост-дайджест по 2-3 лучшим сюжетам. Рамка: "Three things
     I read this week that stuck with me" (не дословно, вариации). По каждому пункту:
     что случилось одной строкой + почему это интересно одной-двумя строками. Без
     глубокого анализа. 120-170 слов.
   - DRAFT 2 (digest, short): тот же дайджест, но 80-110 слов, суше, без вступления.
   - DRAFT 3 (single): один лучший сюжет разобран чуть глубже — как раньше,
     структуры A/B/C на выбор модели.
   Владелец выбирает между двумя длинами дайджеста и одним одиночным постом.

2. Планка тона — добавить блок:
   TONE CEILING: The author is a 2nd-year student, not a professor. If a sentence
   sounds like a bank research note, simplify it. Prefer "X grew faster than Y"
   over "the differential in growth trajectories". No jargon where a plain word
   exists. It is fine for the post to be simple; it is not fine for it to be
   pretentious. Красивое слово, которое студент не употребил бы в разговоре, — ошибка.

3. Всё остальное сохранить: проверяемые цифры, запрет вопросительной позиции,
   первое лицо только про реально сделанное, английский формат чисел, пробелы.

## T8c — вердикт по черновикам и полякоцентричный скоринг

Делать после T8b. Обе правки — в существующие промпты, новых запросов Gemini НЕ добавлять.

### 1. RANK_PROMPT: аудитория

Владелец определил аудиторию: польские финансы в первую очередь, затем те, кто смотрит
на Польшу и CEE снаружи, затем ИИ-темы через призму экономики и бизнеса.

Добавить в критерии скоринга прямой вопрос: would someone working in Polish finance
raise an eyebrow at this? При равном качестве сюжет с польским/CEE углом обязан
получать балл выше абстрактного глобального. ИИ-сюжеты оцениваются через экономический
смысл (capex, маржа, рынок труда, регулирование), а не через новизну модели.
Чисто американская внутрянка без последствий для Европы/Польши — минус к баллу.

### 2. DRAFT_PROMPT: вердикт после каждого черновика

После FIGURES/SOURCE/WHY_THIS_ONE добавить три строки:

VERDICT: POST | MAYBE | SKIP
WHY: одна строка — главная причина вердикта
CHECK_FIRST: одно конкретное действие перед публикацией (какую цифру и где сверить,
что перечитать), или "-" если POST уверенный

Ключевой фильтр вердикта — критерий владельца, вставить в промпт близко к тексту:
"Could the author answer the first follow-up question in the comments himself?
He is comfortable with: financial accounting, DDM/CAPM valuation, bank financials,
Polish macro, ETFs, crypto basics, brokerage business models. If the post's core
mechanism sits outside this list, the verdict cannot be POST — at most MAYBE with
CHECK_FIRST naming what he must actually understand before publishing."

Второй фильтр: если сюжет очевидно будет во всех лентах через день-два и в черновике
нет собственного добавления (расчёта, польского угла, сопоставления) — SKIP с
причиной "commodity news, no edge".

Вердикт даётся КАЖДОМУ из трёх черновиков независимо. Допустимо, чтобы все три
получили SKIP — это честный результат дня без материала, так и писать.

## T8d — контекстный призыв и верификатор цифр

После T8c. Верификатор — самая ценная часть всего T8, делать тщательно.

### 1. DRAFT_PROMPT: закрывающий вопрос (не всегда)

Добавить: максимум ОДИН из трёх черновиков может заканчиваться вопросом, и только
таким, на который человек из индустрии ответит лучше автора — приглашение экспертизы,
не просьба валидации. Вопрос обязан вытекать из содержания поста и называть конкретику
(структуру импорта, механику комиссий, конкретный сегмент). Generic-формулы запрещены
как и раньше: "What do you think", "Thoughts?", "Agree?", "пишите как считаете".
Дайджест-посты могут заканчиваться просто последним пунктом — принудительный вопрос
в каждом посте сам по себе паттерн.

### 2. src/verify.py — верификатор цифр (НЕ редактор)

Принцип: система НЕ исправляет черновики. Та же модель, что ошиблась при извлечении,
не найдёт свою ошибку при исправлении, а молчаливое автоисправление отключает последнюю
линию обороны — глаза владельца. Верификатор сужает ручную проверку с "перечитай релиз"
до "посмотри вот эту одну цифру".

Два уровня:

a) Машинный, без LLM, бесплатный:
   - распарсить FIGURES каждого черновика: (число, заявленный источник)
   - нормализовать число (убрать пробелы/запятые/точки разрядов, учесть польский
     формат "31,0" == "31.0")
   - проверить посимвольное вхождение нормализованного числа в догруженный текст
     соответствующего сюжета (s["body"])
   - числа из блока FRESH DATA сверять с самим блоком (они верифицированы по построению)
   - итог по каждому числу: FOUND / NOT_FOUND / NO_SOURCE_TEXT

b) LLM-контекстный, один запрос на весь прогон, только для черновиков с
   VERDICT POST|MAYBE и только для чисел со статусом FOUND:
   промпт получает пары (предложение из черновика с числом, фрагмент источника
   вокруг того же числа) и отвечает по каждому: MATCH / MISMATCH + одна строка почему.
   Ловит подмену контекста: год не тот, "рост НА x%" против "рост ДО x%",
   квартал против года, штуки против процентов.

Вывод в сводку, под каждым черновиком:

  ЦИФРЫ: ✅ verified (3/3 found, context ok)
     или ⚠️ "4.8%" not found in source (closest in text: "4,9%") — исправь руками
     или ❌ источник не догружен — цифры под твою ответственность

Правило вердикта: если хоть одно число NOT_FOUND или MISMATCH, VERDICT черновика
принудительно понижается до MAYBE, CHECK_FIRST указывает конкретное число и место.

### Бюджет квоты

+1 запрос на прогон (только уровень b, и только если есть что проверять).
Итого 3 запроса из 20. Если черновиков с POST|MAYBE нет или все цифры NOT_FOUND /
NO_SOURCE_TEXT — LLM-уровень пропускается, расход остаётся 2.

### Приёмка T8d

- [ ] число, отсутствующее в источнике, помечается ⚠️ с ближайшим совпадением из текста
- [ ] подмена контекста (не тот год / "на" vs "до") ловится уровнем b как MISMATCH
- [ ] черновик с проблемной цифрой автоматически понижен до MAYBE
- [ ] при ✅ владельцу не нужно открывать первоисточник вообще
- [ ] расход квоты: 3 при наличии проверяемых черновиков, 2 без них
- [ ] верификатор ничего не переписывает в черновиках
