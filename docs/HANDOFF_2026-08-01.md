## ПРАВИЛА РАБОТЫ (выстраданы на этой неделе)

- **Claude Code НЕ делает живых прогонов и не вызывает Gemini.** Тесты только на моках.
  Живые запуски — владелец. Нарушалось трижды, каждый раз съедало квоту и путало
  диагностику.
- **Перед Run workflow — `git push`.** Actions гонит код из origin. Дважды ловили
  «фиксы не работают», а это был старый код.
- Бот коммитит `state/seen.json` и `state/metrics.json` из Actions → перед push
  часто нужен `git pull --rebase`. Это норма, не конфликт.
- Приёмка после каждой части ТЗ, коммит после приёмки.
- Диффы промптов (RANK/DRAFT) владелец смотрит глазами до боевого прогона —
  это единственное место, где регрессия не видна на моках.
  Смотреть так: `git diff <от> <до> --output=diff.txt -- src/brain.py`, файл прикрепить.
- Внешние советы (в т.ч. LLM-ревью) фильтровать: добавляет ли failure surface,
  ломает ли калибровку промптов, не scope creep ли.

## КАЛИБРОВКА ПРОМПТОВ (src/brain.py) — не откатывать

**RANK_PROMPT**: жёсткая отбраковка, требование разброса оценок, angle до 35 слов с
конкретным механизмом, запрет выдуманных цифр. Правило 5 (AUDIENCE): польские финансы
первыми, при равном качестве польский/CEE угол выше абстрактного глобального; ИИ
оценивается через экономику (capex, маржа, рынок труда, регулирование), не через новизну
модели; чисто американская внутрянка без последствий для Европы — минус.

**DRAFT_PROMPT**: три фиксированных черновика — digest (120-170 слов), digest-short
(80-110), single (структуры A/B/C). TONE CEILING (студент, не профессор; «красивое слово,
которое не сказал бы вслух» — ошибка). Позиция объясняющая, не вопросительная («I might be
wrong», «What am I missing» запрещены). Первое лицо ТОЛЬКО про реально сделанное. Числа
только из догруженного текста или FRESH DATA. Английский формат чисел. Максимум ОДИН из
трёх черновиков заканчивается вопросом, и только приглашением экспертизы с конкретикой.
VERDICT/WHY/CHECK_FIRST у каждого черновика; фильтр «ответит ли автор на первый уточняющий
вопрос» + список компетенций (фин. учёт, DDM/CAPM, банковская отчётность, польская макра,
ETF, крипто-базис, модели брокеров); «commodity news, no edge» → SKIP; все три SKIP —
валидный исход.

**Принцип верификатора**: verify.py — НЕ редактор. Автоисправление запрещено
принципиально: та же модель не найдёт свою ошибку, а молчаливая правка отключает
последнюю линию обороны — глаза владельца.
