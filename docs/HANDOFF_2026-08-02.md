  семь отдельных коммитов (b84e212 … f6548ee) плюс один коммит по итогам живого
  прогона (842a9b3).

  `git diff --output=diff.txt -- src/brain.py` (порядок флагов важен — `--output`
  до `--`, иначе git молча трактует его как путь).
- Гипотезы о причине бага проверять по коду, а не принимать на веру — T10b это

## КАЛИБРОВКА ПРОМПТОВ (src/brain.py) — не откатывать

**RANK_PROMPT**: не тронут во всём T10 (запрещено правилами ТЗ).

**DRAFT_PROMPT**: единственная правка T10 — секция FIRST PERSON (T10g.1).
Раньше сама же разрешала "compared two numbers" как легитимную работу автора и
даже приводила "I compared the two figures Rolls-Royce reported" как GOOD-пример —
это и породило реальный баг ("I compared these figures from the RynekPierwotny
report" в боевом прогоне, хотя сравнивала модель, не студент). Теперь: сравнения,
расчёты, чтение отчёта целиком, посещение мероприятия — НИКОГДА не первым лицом
автора. Сама связь между цифрами в посте остаётся, но формулируется про цифры
("these two numbers sit oddly next to each other"), не про действие автора.
Живой прогон 02.08 подтвердил: DRAFT 3 использовал именно новую формулировку.

Остальное не менялось: три фиксированных черновика (digest 120-170 слов,
digest-short 80-110, single A/B/C), TONE CEILING, позиция объясняющая, числа
только из текста/FRESH DATA, VERDICT/WHY/CHECK_FIRST на каждый черновик.

**Принцип верификатора**: verify.py не редактор, автоисправления нет и не будет —
T10c усилил САМ ПОИСК (что считается найденным), но никогда не трогал это правило.

### T10 — семь частей, все приняты, плюс ревью живым прогоном

Написан по факту боевого прогона 01.08.2026 (run 30696216445, не 83246151022 —
это число из ТЗ не соответствовало ни одному реальному run id, артефакт
`digest-log-30696216445` содержал только сводные INFO-строки, не текст сообщений;
реальный текст владелец прислал вручную, скопировав из Телеграма).

- **T10a** (`b84e212`) — чанкер переписан вокруг рекурсивного лоссless-разбиения
  (блок → абзац → предложение → жёсткий разрез без разрыва URL), инвариант
  `"".join(chunks) == text` доказан по построению через regex нулевой ширины, а не
  проверен постфактум. Попутно найдено и закрыто: длина куска проверялась ДО
  `_to_html`, а `<a href>`-обёртка и экранирование кавычек могут раздуть кусок
  за реальный лимит Telegram уже ПОСЛЕ проверки (один кусок фикстуры вырос с
  3329 до 3973 из 4096 — запас в 123 символа, не гарантия). `_chunks`/
  `_pieces_within_limit` теперь меряют по `_to_html`-результату, включая
  последний эшелон (жёсткий разрез с уменьшением лимита, пока не влезет).
- **T10b** (`272cc92`) — гипотеза владельца («дедуп смешивает URL») проверена по
  коду и опровергнута: `dedupe_by_title` оставляет URL выжившей записи как есть.
  Настоящая причина: `main.py` строил `domain_urls` плоским словарём
  `{source: url}` — при нескольких сюжетах с одного домена (обычное дело для
  bankier.pl) поздняя запись стирала раннюю, и `deliver._wrap_bare_domains`
  подставляла этот единственный URL везде, где встречался голый домен, включая
  метку `it.source` в списке СЮЖЕТЫ — с SOURCE черновиков вообще не связанную.
  `build_domain_urls()` теперь включает домен только при ровно одном URL на
  домен; неоднозначные — не угадываются, остаются простым текстом. Плюс
  вырезание utm-хвостов при рендере (посегментно по `&`/`=`, не через
  `parse_qsl`/`urlencode` — тот раунд-трип незаметно перекодировал нетронутые
  параметры, поймано существующим тестом на `ceid=US:en`).
- **T10c** (`d196392`) — тот же класс диагностики: 1/6 found при девяти парах в
  FIGURES объяснялось не арифметикой знаменателя (она была верна), а тем, что
  `charts.parse_figures` молча ронял диапазоны ("80,000 to 120,000") и даты
  словом-месяцем ("August 1, 2026") на этапе regex — 9 пар превращались в 7 ещё
  до того, как verify.py их видел. Плюс верификатор искал только английские
  реконструкции числа и никогда — цитату, которую модель уже сама указала в
  FIGURES ("406 tys."). Добавлены: поиск по цитате первым эшелоном, польские
  формы разрядов (пробел/НБСП/узкий НБСП) и словами (tys./mln/mld/proc.),
  симметричная граница предложения (T9 чинил только конец, начало цеплялось за
  десятичную точку предыдущего числа), гейт «ближайшее» только для чисел
  одного порядка величины. Результат на реальных данных DRAFT 1: 1/6 → 8/8.
- **T10d** (`8650457`) — `verify_drafts()` теперь возвращает третьим значением
  структурные блоки (не только плоский текст) — рендереру не нужно заново
  парсить свой же вывод. Новые `render_summary`/`render_draft_message`: ЦИФРЫ
  в максимум три строки по категориям, список сюжетов без «неочевидно» и без
  второй ссылки (просто печатаем реальный URL сюжета — `_to_html` сам сделает
  его доменом-ссылкой, безопасно даже при коллизии доменов из T10b), заголовок
  черновика печатает рендерер, служебный блок максимум три строки. Старый
  `build_message()` не удалён — кормит `digest.log` полным отчётом (FIGURES,
  оба URL, «неочевидно», сырые поля модели) вместо Telegram.
- **T10e** (`987fa67`) — `charts.stat_card`/`charts.quote_card` (типографика,
  без запросов к Gemini, одна раскладка). `figures_chart` перенацелен с DRAFT 1
  на DRAFT 3 (после T8b DRAFT 1 стал 2-3-сюжетным дайджестом, условие «числа

  попадают только числа со статусом FOUND. `main.draft_card()` маршрутизирует
  по номеру черновика и обёрнут в try/except на каждый черновик отдельно.
- **T10f** (`46a69bc`) — HICP старше 60 дней теперь не печатается вовсе (было —
  печаталась с плашкой «старше N мес!»). Фильтр живёт в
  `numbers.eurostat_hicp()`, поэтому действует сразу везде (сводка, лог,
  FRESH DATA для модели) без правок в main.py — последнее особенно важно:
  протухшая цифра в FRESH DATA могла бы уйти в черновик как «свежая».
- **T10g** (`f6548ee`) — DRAFT_PROMPT (см. выше), имя модели в логе, каскад
  котировок yfinance→stooq (было наоборот — stooq стабильно отдавал

### Ревью живым прогоном (`842a9b3`, 02.08.2026)

Владелец явно санкционировал один живой `.\run.ps1 dry` — этот прогон, а не
дополнительные юнит-тесты, нашёл три реальных бага:

1. `charts._VALUE` матчил диапазон только через "to". Живые черновики использовали
   и "and" ("2.8 and 3.2 million tons" — строка целиком терялась, тот же класс
   бага, что T10c req 3, просто другой союз), и слитный дефис без пробелов
   ("2.8-3.2 million tons" — хуже: общий `-`-разделитель "value - source"
   откусывал половину диапазона себе, `value="2.8"`, `source="3.2 million tons
   -> Source [3] text"` с настоящей стрелкой внутри мусорного source).
   Исправлено: диапазон-дефис теперь часть числового ядра (жадно, без пробелов —
   не может столкнуться с разделителем, у которого после дефиса всегда пробел
   или буква), плюс "and" рядом с "to" как раздельный союз.
2. `draft_card(block, 3)` пробовал только `figures_chart` без фолбэка. Реальный
   DRAFT 3 дал 0/4 FOUND → `figures_chart` вернул `None` (меньше 2 значений
   после фильтра) → картинка не рисовалась вовсе, хотя «у каждого из трёх
   черновиков ровно одна картинка» не делает для третьего исключения. Теперь
   любой отказ `figures_chart` (не только 0 FOUND) откатывается на `quote_card`.
3. `stat_card`/`quote_card` писали в путь по имени темы (`stat_dark.png`) без
   привязки к черновику. Когда в одном прогоне и черновик 1, и черновик 2
   рисовали stat-карточку, второй вызов молча перезаписывал файл первого ДО
   того, как `deliver.send_photo` успевал его прочитать — черновику 1 ушла бы
   картинка черновика 2. Добавлен параметр `key` (main.py передаёт номер
   черновика), пути теперь `stat_1_dark.png`/`stat_2_dark.png` и т.д.

Все три воспроизведены на точных данных из живого лога до и после фикса,
закрыты регрессионными тестами, 175 тестов зелёных.
