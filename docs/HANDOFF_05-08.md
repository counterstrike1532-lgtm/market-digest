## 2. Что сделано сегодня: T14b

Три независимых бага одного класса — тихая потеря вместо явного сигнала.

1. **`src/charts.py`** — `_NUM_CORE`/`_VALUE` принимает число со словом:
   закрытый список квалификаторов (`over, about, roughly, nearly, around,
   almost, under, approximately`) + числительные `one..twelve` как ядро.
   Такие пары теперь попадают в знаменатель честно, со статусом UNPARSED.
   Двусловные квалификаторы (`more than`, `up to`, `at least`) —
   **сознательно вне охвата итерации**, зафиксировано в докстринге.
2. **`src/verify.py`** — `_core_number_variants` при пустом ядре возвращает
   `[]`, не `[""]`. `text.find("")` всегда даёт 0, пустой вариант ложно
   засчитывался как найденное ядро в начале любого тела. Шаг 1 эту мину
   активировал, шаг 2 закрыл — потому один коммит.
3. **`src/main.py`** — `render_draft_message`, пять веток в порядке проверки:
   `offending непуст` (не тронута) → `denom == 0` → `found == denom` (✅) →
   `found == 0` → `0 < found < denom`.

**Находка сессии, которой не было в ТЗ:** случай `0 < found < denom` при
пустом `offending` достижим, потому что FRESH DATA матчится через
`data_text` в обход `bodies` (`verify.py:424`), а `combined_body` общий на
весь черновик, а не per-pair (`verify.py:414`). Отдельная ветка и отдельная
строка: `— часть чисел не сверена, источник не догружен`.

**Как это будет выглядеть в Телеграме.** Вчерашний черновик, где стояло
`✅ 1/1` при четырёх числах, теперь даст:
`MAYBE — сверь over 67 days, four days longer, seven residential buildings`
с понижением вердикта. Три UNPARSED честно попадают в `_offending`.
