# ТЗ T6 — перенос на GitHub Actions

Цель: сводка приходит в Телегу каждое утро сама, компьютер включённым не нужен.
`digest.cmd` остаётся для ручных прогонов вне расписания.

Работать по шагам, после каждого — стоп и подтверждение. Читай `CLAUDE.md`, раздел «ГРАБЛИ».

---

## Шаг 0. Предварительные проверки (до любых правок)

```bash
git status --short              # должно быть чисто
git ls-files | grep -i secret   # должно быть пусто
git log --oneline --all -- secrets.ps1   # должно быть пусто
```

Если `secrets.ps1` где-то всплывёт — останови всё и скажи мне. Репозиторий будет
публичным, ключ в истории означает его компрометацию.

Дополнительно проверь, что в истории нет случайно закоммиченных логов прогонов
(`dry_run_output*.txt` и подобных). Если есть — добавь маску в `.gitignore`.

## Шаг 1. Исправить `.github/workflows/digest.yml`

Файл написан до сегодняшних правок и содержит проблемы. Перепиши с учётом всего ниже.

### 1.1 Инъекция через inputs (обязательно)

Сейчас:
```yaml
run: python -m src.main --hours ${{ github.event.inputs.hours || '26' }}
```

Значение input подставляется прямо в shell-команду. Это классический script injection,
и линтеры GitHub такое помечают. Передавай через `env`, а в скрипте читай переменную:

```yaml
env:
  HOURS: ${{ github.event.inputs.hours || '26' }}
run: python -m src.main --hours "$HOURS" ...
```

### 1.2 Concurrency

Добавь группу, чтобы ручной и плановый прогон не столкнулись на push:

```yaml
concurrency:
  group: digest
  cancel-in-progress: false
```

`cancel-in-progress: false` намеренно: прерывать прогон на середине незачем, он уже
потратил квоту Gemini.

### 1.3 Конфликт при коммите seen.json

Сейчас `git push` без подтягивания. Если между checkout и push в ветку что-то попало
(например, ты сам закоммитил с ноутбука), push упадёт. Нужно:

```bash
git pull --rebase --autostash origin master || true
git push
```

Плюс шаг коммита не должен валить весь прогон: сводка уже отправлена, падать на
служебном коммите бессмысленно. Заверни в `continue-on-error: true` или проверку.

### 1.4 Уведомление о падении

Главная дыра: если прогон сломается, владелец об этом не узнает — просто не придёт сводка,
и непонятно, это тишина в новостях или поломка. Добавь финальный шаг:

```yaml
- name: Notify on failure
  if: failure()
  env:
    TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
    TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}
    RUN_URL: ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}
  run: |
    curl -s -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendMessage" \
      -d chat_id="$TELEGRAM_CHAT_ID" \
      -d disable_web_page_preview=true \
      --data-urlencode text="Дайджест упал. Лог: $RUN_URL"
```

### 1.5 Версия Python

Стоит 3.12, локально у владельца 3.14. Проверь, что код идёт на 3.12, или подними до 3.13.
Не важно какую выбрать, важно чтобы совпадало с тем, на чём тестируешь.

### 1.6 Артефакт с логом

Добавь загрузку лога прогона как артефакт (`actions/upload-artifact@v4`, `if: always()`,
retention 7 дней). Тогда при разборе проблем не надо лазить по веб-интерфейсу построчно.

## Шаг 2. Создать репозиторий

**Публичный.** У приватных квота Actions-минут (3000/мес на Pro) уже занята другим ботом
владельца; у публичных на стандартных раннерах минуты не расходуются вообще.

```bash
gh repo create news-digest --public --source=. --push
```

Если `gh` не установлен — создать через веб-интерфейс и добавить remote вручную.

## Шаг 3. Секреты и переменные

Settings → Secrets and variables → Actions.

**Secrets** (зашифрованы, в логах маскируются):
| Имя | Обязателен |
|---|---|
| `GEMINI_API_KEY` | да |
| `TELEGRAM_BOT_TOKEN` | да |
| `TELEGRAM_CHAT_ID` | да |
| `FRED_API_KEY` | нет |

**Variables** (видны в логах, это нормально):
| Имя | Значение |
|---|---|
| `GEMINI_MODEL` | `gemini-3.5-flash,gemini-3.6-flash,gemini-3.1-flash-lite` |

Значения запрашивай у владельца, сам не подставляй и в файлы не пиши.

## Шаг 4. Ручной прогон и проверка

Actions → `news digest` → Run workflow.

Что должно быть в логе:
- `эвристический предотбор: оставили 100 из ~270`
- отбор одним запросом, без батч-варнингов
- `расход квоты Gemini: 2 запроса`
- сводка пришла в Телегу
- шаг коммита создал `state: seen items YYYY-MM-DD` и запушил

**Ожидаемые отличия от локального прогона, это НЕ баги:**
- Reddit по-прежнему 403, а с IP GitHub возможно и жёстче
- `enrich.py` догрузит меньше статей, чем локально: издатели режут IP дата-центров
  сильнее, чем домашние. Если станет совсем плохо (0-1 из 6) — зафиксируй как отдельную
  задачу, но не лечи в рамках T6
- расписание GitHub Actions запаздывает на 5-20 минут, иногда прогон пропускается совсем.
  Это известное поведение платформы, не наша ошибка

## Шаг 5. Проверить повторный прогон

Запусти второй раз вручную и убедись, что `state/seen.json` работает: во второй сводке
не должно быть сюжетов из первой. Если повторяются — механизм памяти сломан при переносе.

Учти, что второй прогон съест ещё 2 запроса квоты (всего 20 в сутки на модель).

## Чего не делать

- Не тащить в Actions Playwright и коллектор X — он локальный по замыслу (T3)
- Не менять `RANK_PROMPT`, `DRAFT_PROMPT`, `SCORE_PROMPT` — они откалиброваны
- Не делать репозиторий приватным «для безопасности»: секреты и так в Secrets,
  а приватный съест дефицитную квоту минут
- Не добавлять зависимости
- Не запускать прогоны лишний раз: квота 20 запросов в сутки на модель, каждый прогон
  стоит 2, и она общая с локальными запусками

## Заметка на будущее

Плановые воркфлоу GitHub отключает после 60 дней без активности в репозитории. Здесь это
самоподдерживается: бот ежедневно коммитит `state/seen.json`, и это считается активностью.
Но если дайджест будет надолго выключен, расписание придётся включать заново вручную.
