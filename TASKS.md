## T2 — Настройка качества отбора (делать первой)

Владелец запустит `.\run.ps1 dry` и покажет вывод. Твоя задача — по живому результату
довести `RANK_PROMPT` и `DRAFT_PROMPT` в `src/brain.py`.

На что смотреть в выводе:

1. **Разброс оценок.** Если снова всё сваливается в 7-8 — усиль требование разброса.
   Вариант: требовать ровно одну оценку 9+ на батч, или заставить ранжировать внутри батча
   и выдавать позицию, а не абсолютный балл.
2. **Структуры черновиков.** Проверь, что три черновика реально разные (SHAPE A/B/C) и не
   начинаются одинаково. Если модель всё равно шаблонит — разнеси генерацию на три
   отдельных вызова, по одной структуре в каждом.
3. **Поле FIGURES.** Каждое число должно иметь источник. Если модель пишет числа при
   `SOURCE TEXT: (unavailable)` — правило нарушено, усиливай запрет.
4. **Хэштеги.** Если лезут генерик-теги (#finance, #GPW, #macroeconomics) — запрети совсем.
5. **Мусор в сюжетах.** Что прошло отбор, но по мнению владельца шлак — добавь в список
   критериев отбраковки его словами.

Не переписывай промпты целиком «чтобы стало лучше». Меняй адресно и объясняй каждую правку.

## T3 — Коллектор X/Twitter

Владелец согласен рисковать **отдельным** аккаунтом X. Не основным.

### Ключевое архитектурное решение

Работает **локально, не в GitHub Actions.** X агрессивно флагует IP дата-центров: с раннера
GitHub сессия проживёт дни, с домашнего IP — недели или месяцы.

```
локально (Task Scheduler, 1-2 раза в день)
  src/collect_x.py -> state/x_latest.json -> git commit && push
основной прогон
  src/main.py читает state/x_latest.json, если он свежий (< 20 часов)
```

Нет файла или он старый — дайджест собирается без X, без ошибки. Обязательно.

### Реализация

- Playwright, в отдельный `requirements-local.txt` (чтобы Actions его не тянул)
- `python -m src.collect_x --login` — видимый браузер, владелец логинится руками,
  сессия в `.secrets/x_state.json`. Проверь, что путь в `.gitignore`
- обычный запуск headless, восстанавливает сессию, идёт на **List**, не в домашнюю ленту:
  список детерминированный и курируемый. URL списка — в `config/sources.yaml`,
  новая секция `twitter: {list_url: ..., min_faves: 30, max_tweets: 60}`
- скроллит до `max_tweets` или до твитов старше 24 часов
- забирает: автор, текст, ссылка, лайки, ретвиты, время
- фильтр: отбросить ретвиты, ответы и всё ниже `min_faves`
- конвертирует в `Item` из `src/collect.py` (`tag="x"`, `weight=0.9`, `social=лайки`),
  сериализует в `state/x_latest.json` с полем `collected_at`
- человеческие паузы `random.uniform(1.5, 4.0)`, окно 1280x900, реалистичный UA
- селекторы не нашлись — внятная ошибка «разметка X изменилась», а не тихое падение

Отдельно `docs/setup_x.md`: как создать burner-аккаунт, собрать List, поставить
Task Scheduler на Windows, что делать когда сессия отвалится.

## T4 — Bluesky (риска ноль)

Официальный публичный API, бесплатный. Часть finance/AI людей туда дублирует.

`src/collect_bluesky.py`: `com.atproto.server.createSession` (env `BSKY_HANDLE` /

Только `requests`, без SDK. Отдаёт `Item` с `tag="bluesky"`.

Живёт в основном пайплайне, Actions не мешает.

## T5 — Скорер черновиков

`src/score_draft.py` — CLI: подаёшь текст поста, получаешь отчёт перед публикацией.

Без LLM: длина 110-170 слов; есть хотя бы одно число; нет запрещённых слов из
`DRAFT_PROMPT`; нет engagement-bait в конце; хэштегов 0-1; нет ссылок в теле;
не открывается риторическим вопросом.

Через Gemini: есть ли личная ставка или это пересказ; **не в вопросительной ли позиции**
написан пост (главный флаг); звучит как студент или как консультант; пройдёт ли
за человеческий текст.

Вывод PASS/FAIL по пунктам плюс 2-3 конкретные правки. Пост за владельца не переписывать.
